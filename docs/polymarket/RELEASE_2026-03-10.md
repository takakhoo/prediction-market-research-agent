# Release Notes - 2026-03-10

This update consolidates the agent stack around production-style operation: source ingestion, market classification, Telegram discovery, listener execution, and live runtime observability.

## What Was Added

## 1) Prompt Runtime Refactor

Prompts are now loaded from editable runtime files in `configs/prompts/`:

- `local_market/`
- `telegram_query_planner/`
- `telegram_channel_reviewer/`
- `telegram_message_matcher/`

This makes tuning immediate (no code edit required) and keeps prompt versions explicit.

## 2) Telegram Discovery Improvements

- Query planner output includes Google-style `site:t.me` queries.
- SERP bootstrap is now integrated in discovery runtime.
- Official channel first-pass + TDLib resolution is wired into discovery flow.

Key file:

- `src/polymarket/google_serp.py`

## 3) AI Message Matcher (Optional)

Listener message-to-market matching can now run via AI JSON classification.

- Feature flag: `AI_ENABLE_MESSAGE_MATCHER=true`
- Model: `AI_TELEGRAM_MESSAGE_MATCHER_MODEL`
- Dedicated prompt files:
  - `configs/prompts/telegram_message_matcher/system.txt`
  - `configs/prompts/telegram_message_matcher/user.txt`

Safety behavior:

- If AI provider fails/times out, matcher falls back to heuristic mode and listener keeps running.

## 4) OpenRouter-Compatible Config Path

Added matcher-specific provider overrides so only message-matching can use a different provider/model:

- `AI_MESSAGE_MATCHER_API_KEY`
- `AI_MESSAGE_MATCHER_BASE_URL`
- `AI_MESSAGE_MATCHER_HTTP_REFERER`
- `AI_MESSAGE_MATCHER_APP_NAME`

General OpenAI-compatible headers are also supported in runtime client.

## 5) Dashboard / UX Expansion

Workspace dashboard now includes:

- `GET /market-rail`: high-speed market classification rail (manual correction workflow)
- `GET /agent-runtime`: live runtime status and event feed
- Expanded backtest UI components under `src/workspace_dashboard/templates/backtest/`

## 6) Runtime Telemetry for Workers

Telegram worker writes runtime state/events to DB for observability:

- `agent_runtime_status`
- `agent_runtime_events`

This powers live progress pages and makes failures/retries auditable.

## 7) Storage Pressure Controls

To avoid runaway database growth:

- snapshots are off by default in env templates (`MARKET_STORE_SNAPSHOTS=false`)
- cleanup utility added:
  - `scripts/compact_market_storage.py`

Use this for truncating snapshots and compacting analysis history safely.

## 8) Env and Script Updates

Updated templates and runners:

- `.env.example`
- `configs/sources/polymarket_runtime.template.env`
- `scripts/run_telegram_market_agent.py`
- `scripts/ingest_markets.py`
- `scripts/run_workspace_dashboard.sh`
- `scripts/run_discovery_dashboard.sh`

## Quick Validation Checklist

1. Bootstrap Telegram session for the intended runtime session dir.
2. Start workspace dashboard and open:
   - `/market-rail`
   - `/agent-runtime`
   - `/backtest`
3. Run one Telegram agent cycle (`--once`) with SERP enabled.
4. Confirm DB writes in:
   - `telegram_channels`
   - `channel_market_map`
   - `telegram_messages`
   - `message_market_matches`
   - `agent_runtime_status`
   - `agent_runtime_events`

## Notes

- `AUTH_KEY_DUPLICATED` still means multiple processes are sharing one TDLib session key/session dir.
- Keep one active process per `TELEGRAM_SESSION_DIR`.
